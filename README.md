# R²-SAFE (ต้นแบบเชิงวิจัย)

ต้นแบบเว็บของระบบช่วยตัดสินใจเลือกกลยุทธ์การบริหารความปลอดภัยสถานศึกษา บนฐานความเสี่ยงและความพร้อมขององค์กร (ประกอบดุษฎีนิพนธ์ ร่าง)

- เว็บ: https://sarawut2206.github.io/risk-safe/
- ใช้ข้อมูลจำลอง ไม่เก็บและไม่ส่งข้อมูลผู้ใช้ ประมวลผลในเบราว์เซอร์เท่านั้น
- เกณฑ์ ตารางตัดสินใจ และคลังมาตรการ 68 รายการ (SB-001 ถึง SB-068) เป็นร่าง ยังไม่ตรวจหลักฐานรายข้อ และยังไม่ผ่านเดลฟายและการประเมินโดยผู้ทรงคุณวุฒิ
- หากเกิดเหตุฉุกเฉินจริง ให้ปฏิบัติตามแผนเผชิญเหตุและกฎหมายทันที ระบบนี้ไม่ใช้แทนดุลยพินิจของผู้อำนวยการ

## โครงสร้าง

| ไฟล์ | หน้าที่ |
|---|---|
| `index.html`, `style.css`, `app.js` | หน้าเว็บ |
| `engine.js` | เครื่องคำนวณกลไกตัดสินใจ (ย้ายจากเครื่องมือ Excel ต้นแบบ) |
| `data.js` | คลังมาตรการ ชุดการตัดสินใจ R1–R9 ข้อคำถามความเสี่ยงและ 7-S ข้อมูลตัวอย่างสมมติ |
| `bankloader.js`, `config.js` | โหลดคลังมาตรการจาก Google Sheets (อ่านอย่างเดียว) ตรวจข้อมูลก่อนใช้ ถ้าไม่ได้ใช้ข้อมูลที่ฝังไว้ |
| `apps-script/Code.gs` | โค้ด Google Apps Script (doGet อ่านอย่างเดียว) วางในโครงการ Apps Script แล้ว deploy ดูขั้นตอนในหัวไฟล์ |
| `tests/test_engine.js` | ทดสอบเทียบผลกับ Excel (`node tests/test_engine.js`) |
| `tests/test_bankloader.js` | ทดสอบตัวตรวจและตัวโหลดคลังมาตรการ (`node tests/test_bankloader.js`) |

การจัดลำดับมาตรการ (ข้อ B5): องค์ประกอบ 7-S ที่ช่องว่างสูงสุดก่อน → ลำดับ QSPM (`qpri`, ว่าง = 1) → ระดับหลักฐาน A–D (`evg`) → ลำดับในคลัง มาตรการที่เหมาะแต่เกินทรัพยากรที่มีจะแยกแสดงในรายการ "เกินทรัพยากร" ไม่ถูกตัดทิ้งเงียบ ๆ และมาตรการที่มีเงื่อนไขก่อนดำเนินการจะแสดงสถานะว่าอยู่ในรายการหรือไม่ (ไม่สลับลำดับอัตโนมัติ) ระดับหลักฐานมาจากการค้นรอบแรกเมื่อ 5 พ.ย. 2569 (แหล่งส่วนใหญ่อ่านจากบทคัดย่อ) ยังไม่ใช่การค้นเชิงระบบ

ลำดับ QSPM: ช่อง `qpri` ของมาตรการ (1–20, 1 = ดีที่สุดในประเด็นเดียวกัน, ว่าง = 1) ใช้จัดลำดับภายในกลุ่มเดียวกันตามข้อ B5 ปัจจุบันยังว่างทั้งหมด เพราะยังไม่ได้ทำเดลฟายและ QSPM (โครงอยู่ในไฟล์ R2-SAFE-QSPM-ลำดับมาตรการ-ร่าง.xlsx)

ข้อมูลใน `data.js` ควรแก้ผ่าน commit เพื่อให้มีประวัติการเปลี่ยนแปลง (เช่น แต่ละรอบเดลฟายติด tag) ห้ามนำข้อมูลโรงเรียนจริงหรือข้อมูลบุคคลเข้าที่เก็บนี้

## หน้าตาส่วนเครื่องมือ (V0.4)

ส่วนเครื่องมือประเมินปรับเป็นหน้าตาแบบแอป (มือถือก่อน) ตามต้นแบบภาพที่ผู้วิจัยจัดทำ: หน้าแรก, ข้อมูลโรงเรียนและเอกสาร, ประเมินความเสี่ยง, ประเมินความพร้อม 7-S, PNI, ตาราง R1-R9, กลยุทธ์ และแผนงาน มีแถบเมนูล่าง 5 ปุ่ม

- ไฟล์: `tool.js` (สร้าง HTML ของหน้าเครื่องมือ), `tool.css` (หน้าตา) ส่วน `engine.js` และกฎคำนวณไม่เปลี่ยน ชุดทดสอบเดิมยังผ่านทั้งหมด
- ตัวเลขทุกจุดมาจากเครื่องคำนวณและข้อมูลที่ผู้ใช้กรอกเท่านั้น ส่วนในภาพต้นแบบที่ระบบยังไม่มีข้อมูลรองรับ (กราฟแนวโน้มเหตุการณ์ ตัวชี้วัดผลลัพธ์ ปฏิทินกำหนดส่ง การดึงข้อมูลอัตโนมัติจากไฟล์ SAR) **ไม่ได้ทำเป็นตัวเลขสมมติ** แต่ใช้ข้อมูลที่มีจริงแทน
- การอัปโหลดเอกสารในรายการเอกสาร: จดเฉพาะชื่อไฟล์ ขนาด และวันที่ในหน่วยความจำของเบราว์เซอร์ ไม่อ่านเนื้อหาและไม่ส่งไฟล์ไปที่ใด (หายเมื่อรีเฟรช) ส่วนการ์ด "อ่านข้อมูลจากแผนปฏิบัติการ" อ่านข้อความใน PDF ที่ผู้ใช้เลือกด้วย pdf.js ในเบราว์เซอร์ของผู้ใช้เอง (ไม่อัปโหลด) ดูหัวข้อ V0.9
- ขนาดโรงเรียนจัดจากจำนวนนักเรียนเพื่อแสดงผลเท่านั้น ยังไม่ใช้ในการคำนวณ


## กลไกตัดสินใจ การอธิบายเหตุผล วงจรเรียนรู้ และการพิสูจน์ผล (V0.6)

- `decision.js` กฎรายแกน (A1–A3, B1–B3) และกลยุทธ์เฉพาะช่อง R1–R9 ตัวบังคับกฎ (สลับมาตรการที่ไม่ตอบเงื่อนไขพร้อมบันทึกเหตุผล) ตัวอธิบายทำไมเลือก/ไม่เลือก และตรวจความครอบคลุมของคลัง ปิดตัวบังคับกฎได้ในหน้า "กฎตัดสินใจ" เพื่อดูผลเดิมที่ตรงกับ Excel
- `learn.js` บันทึกผลรายมาตรการ รอบประเมินซ้ำ รายงานไม่ระบุชื่อ และกฎเสนอปรับคลัง L1–L7 (ไม่ปรับคลังอัตโนมัติ)
- `evalkit.js` แบบประเมินผู้เชี่ยวชาญ (กรณีจำลอง 27 กรณี + 15 ข้อ) แบบประเมินผู้บริหาร (4 ด้าน + SUS) ตัววิเคราะห์ และตารางตัวชี้วัดความสำเร็จ `stats.js` สถิติ (ตรวจเทียบ scipy)
- `tool2.js`/`tool2.css` หน้าจอ: กฎตัดสินใจและเหตุผล · ติดตามผลและบทเรียน · ประเมินนวัตกรรม · ห้องวิเคราะห์ของผู้วิจัย
- ทุกกฎ เกณฑ์ และข้อคำถามเป็นร่างของผู้วิจัย ยังไม่ผ่านเดลฟาย IOC หรือการรับรองจริยธรรม ไม่มีผลวิจัยในเว็บ ถ้าไม่มีข้อมูลตารางตัวชี้วัดแสดง "ยังไม่มีข้อมูล"
- `examples/` คือไฟล์สมมติ (synthetic) สำหรับทดสอบห้องวิเคราะห์เท่านั้น สร้างด้วย `node tools/make_examples.js` เว็บแสดงแถบเตือนเมื่อนำเข้า
- ข้อมูลที่ผู้ใช้กรอกอยู่ในเบราว์เซอร์ ส่งออกเป็นไฟล์ในเครื่องเมื่อผู้ใช้สั่งเท่านั้น รายงานส่งผู้วิจัยไม่มีชื่อโรงเรียนและข้อความอิสระโดยปริยาย

ทดสอบ: `node tests/test_engine.js && node tests/test_bankloader.js && node tests/test_decision.js && node tests/test_stats.js && node tests/test_learn.js && node tests/test_eval.js && node tests/test_examples.js`

## การพิสูจน์ความถูกต้องของกลไก (V0.7)

- `tests/test_boundary.js` ค่าตัดทุกจุด กฎยกระดับ กฎเพดาน ครบ 9 ช่อง × 4 ด้าน × 3 ทรัพยากร (108 ฉากทัศน์) เอกภาพ ความไม่ขึ้นกับลำดับข้อ ข้อมูลไม่ครบ

- `tools/sensitivity.js` ความไวของช่อง R ต่อคะแนนคลาดเคลื่อนและค่าตัด (จำลอง) · `tools/simulate_concordance.js` กำลังของเกณฑ์ kappa/alpha ของกรณีจำลอง 27 กรณี (จำลอง) · `tools/map_7s_constructs.js` จับคู่ข้อประเมิน 7-S กับทฤษฎีความพร้อม
- ผลของเครื่องมือเหล่านี้อยู่ใน `analysis/` ผลจากการจำลองไม่ใช่ผลวิจัย
- แก้ข้อบกพร่อง: ค่าตัดใช้ค่าคลาดเคลื่อน 1e-9 กันเลขทศนิยม (เช่น 2.6000000000000005) และแก้ตัวนับเหตุผล "ถูกสลับตามกฎ"

ทดสอบเพิ่ม: `node tests/test_boundary.js` · เทียบ Python: `node tools/dump_for_diff.js 3000 && python tools/diff_test.py`

## ระบบรวบรวมข้อมูลสถานศึกษา (V0.8)

หน้า "เก็บข้อมูลโรงเรียน" (`#portal`) ใช้เก็บข้อมูลจากโรงเรียนตัวอย่าง 180 แห่งผ่านแบบฟอร์ม 3 ชุด: แบบสอบถามความเสี่ยงและความพร้อม (ผู้ตอบ 3 คน/โรงเรียน) · แบบบันทึกจำนวนเหตุการณ์ · แบบตรวจเอกสารนโยบาย

- ไฟล์: `collect.js` (โครงสร้างแบบฟอร์ม ตรวจความครบ แพ็กข้อมูลพร้อมเลขใบรับ รวมผลรายโรงเรียน rwg ICC Spearman) · `tool3.js`/`tool3.css` (หน้าจอผู้ตอบและแดชบอร์ดผู้วิจัย) · `apps-script/collect.gs` (ตัวรับข้อมูลฝั่งเซิร์ฟเวอร์ ตรวจซ้ำทุกข้อ ตรวจรายชื่อและรหัสผ่าน)
- ผู้ตอบ: เข้าด้วยรหัสโรงเรียนและเลือกผู้ตอบ หรือเปิดลิงก์เฉพาะบุคคล (`#form1?s=S001&r=R2`) ร่างบันทึกในเบราว์เซอร์อัตโนมัติ กลับมากรอกต่อได้ มีแถบความคืบหน้าและตรวจก่อนส่ง รองรับมือถือ ไม่มีช่องชื่อบุคคลหรือนักเรียน มีข้อความปลายเปิดเฉพาะตอนที่ 4 (ไม่เกิน 600 อักขระต่อช่อง พร้อมคำเตือนห้ามระบุตัวบุคคล ผู้วิจัยลบข้อมูลที่ระบุตัวได้ก่อนวิเคราะห์)
- โหมด (`config.js`): `collectMode: 'demo'` (ค่าเริ่มต้น ทดลองกรอก **ไม่ส่งข้อมูล**) · `'tryout'` (ทดลองใช้ 30 คน) · `'live'` (เก็บจริง) และ `collectUrl` ที่อยู่เว็บแอปของ `collect.gs` ถ้าว่างไว้ ผู้ตอบดาวน์โหลดไฟล์ JSON ส่งผู้วิจัยแทน (ตัวสำรอง)
- แดชบอร์ดผู้วิจัย: นำเข้ารายชื่อและไฟล์ตอบกลับ · ความครบรายโรงเรียน · โปรไฟล์ R1–R9 ผ่านเครื่องคำนวณและตัวบังคับกฎ (ตรวจ H1: ≥5 จาก 9 ช่อง และไม่มีช่องใดเกิน 50%) · ความสอดคล้องผู้ตอบ (rwg ICC(1)) และสหสัมพันธ์จำนวนเหตุการณ์กับ L เฉลี่ย · ส่งออก CSV · ลิงก์รายบุคคล
- ติดตั้ง `collect.gs`: ดูขั้นตอนที่หัวไฟล์ รายการรหัสข้อสำหรับตั้งค่าได้จาก `node tools/print_item_ids.js` ยังไม่เคยทดสอบกับบริการ Google จริง (ทดสอบด้วยสภาพแวดล้อมจำลองเท่านั้น)
- ก่อนเก็บข้อมูลจริงต้องผ่านการรับรองจริยธรรม ตรวจ IOC ทดลองใช้ 30 คน และตรวจความเที่ยง กฎรวมคำตอบข้อยกระดับ (ส่วนใหญ่ของผู้ตอบ) และทรัพยากร (ค่าต่ำสุด) เป็นข้อเสนอของผู้วิจัย รอที่ปรึกษายืนยัน ช่วงงบประมาณเป็นร่าง
- `examples/synthetic-collect-*.json` เป็นข้อมูลสมมติ (`synthetic:true`) สำหรับทดสอบแดชบอร์ดเท่านั้น สร้างด้วย `node tools/make_collect_examples.js` ไม่ใช่โรงเรียนจริงและไม่ใช่ผลวิจัย
- การเปลี่ยนใน `engine.js`: รับ `input.overrideDomains` (บังคับยกระดับรายด้าน) ซึ่งค่าเริ่มต้นไม่เปลี่ยนผลเดิม

ทดสอบเพิ่ม: `node tests/test_collect.js && node tests/test_collect_server.js`

## อ่านข้อมูลจากแผนปฏิบัติการ (PDF) อัตโนมัติ (V0.9)

หน้า "ข้อมูลโรงเรียนและเอกสาร" มีการ์ด "อ่านข้อมูลจากแผนปฏิบัติการ (PDF) อัตโนมัติ" ผู้ใช้เลือกไฟล์แผนปฏิบัติการประจำปีของโรงเรียน ระบบดึงข้อความในไฟล์แล้วเสนอค่าให้ตรวจก่อนนำไปกรอก

- ไฟล์: `planread.js` (ตัวอ่านและกฎดึงข้อมูล ไม่มี DOM) · `planui.js`/`planui.css` (หน้าจอ) · `vendor/pdfjs/` (pdf.js 3.11.174 ลิขสิทธิ์ Apache-2.0 โหลดเมื่อผู้ใช้เลือกไฟล์เท่านั้น)
- ความเป็นส่วนตัว: อ่านไฟล์ในเบราว์เซอร์ของผู้ใช้ ไม่อัปโหลดไฟล์ ไม่ส่งข้อความหรือผลที่อ่านไปที่ใด ผลหายเมื่อรีเฟรช
- ค่าที่อ่านได้: ชื่อโรงเรียน ปีงบประมาณ จังหวัด เขตพื้นที่การศึกษา (และชั้นภูมิ BKK1/BKK2 ถ้าตรง) จำนวนนักเรียน (ตรวจชาย+หญิง=รวม) จำนวนห้อง จำนวนครูและบุคลากร (ตรวจชาย+หญิง=รวม) จำนวนครูแนะแนว แต่ละค่ามีหน้าที่พบ ข้อความต้นฉบับ และระดับความมั่นใจ ผู้ใช้แก้และติ๊กเลือกก่อนนำไปกรอก
- โครงการที่เกี่ยวกับความปลอดภัยและสุขภาวะ: เลือกจากชื่อโครงการด้วยคำสำคัญใน 4 ด้านของภัย พร้อมยอดเงิน ให้ผู้ใช้ติ๊กเลือก ระบบสรุปช่วงงบตามแบบสอบถามของระบบรวบรวมข้อมูล เป็นข้อมูลประกอบ ไม่เข้าไปในการคำนวณ
- ข้อสังเกตจากเนื้อหาแผน: พบ/ไม่พบคำที่เกี่ยวกับเอกสาร D1–D5 และหัวข้อที่เป็นหลักฐานของ 7-S ไม่ใช่การยืนยันว่าโรงเรียนมีหรือไม่มีเอกสาร
- สิ่งที่ระบบไม่ทำ: ไม่ให้คะแนน L, C, D, I ไม่ตัดสินระดับทรัพยากร ไม่แทนการประเมินของผู้ใช้
- ข้อจำกัด: ใช้ได้กับ PDF ที่เลือกข้อความได้ ไม่รองรับภาพสแกน (ยังไม่มี OCR) กฎดึงข้อมูลเขียนจากแผนตัวอย่าง 1 ฉบับ (ตารางจำนวนนักเรียน จำนวนบุคลากร และตารางโครงการ) แผนของโรงเรียนอื่นอาจใช้รูปแบบต่างออกไป ระบบจะแสดง "ไม่พบ" แทนการเดา ฟอนต์บางชนิดทำให้สระอำเพี้ยน ระบบซ่อมให้เฉพาะเอกสารที่พบอาการนี้ ควรตรวจชื่อโรงเรียนเสมอ
- ใช้ 2 ที่: (1) ปุ่ม "อัปโหลดแผนปฏิบัติการ" บนสุดของหน้า "ข้อมูลโรงเรียนและเอกสาร" ในเครื่องมือประเมิน เลือกไฟล์แล้วระบบกรอกให้อัตโนมัติทันที (ชื่อ จำนวนนักเรียน บุคลากร ปี จังหวัด) เพิ่มไฟล์ในรายการเอกสาร และแสดงที่มาของแต่ละค่าไว้ให้ตรวจ ค่าที่กรอกทับของเดิมแก้ได้ที่ช่องโดยตรง (ในที่นี้ไม่ต้องติ๊กเลือกก่อน ต่างจากแบบสอบถาม) (2) ตอนที่ 1 ของแบบสอบถามในระบบรวบรวมข้อมูล (กรอกจำนวนนักเรียน บุคลากร สังกัดพื้นที่ ครูแนะแนว และช่วงงบด้านความปลอดภัย) ในแบบสอบถามจะไม่แสดงชื่อโรงเรียนและจังหวัด และกรอกให้อัตโนมัติเฉพาะค่าที่มั่นใจสูง (จำนวนนักเรียนและบุคลากรที่ชาย+หญิง=รวม และสังกัดพื้นที่ที่ตรงกับรายการ) ส่วนปี ครูแนะแนว และช่วงงบ (ค่าที่ยังไม่แน่ใจ) แสดงให้ผู้ตอบตรวจแล้วกรอกเอง ผู้ตอบแก้ช่องที่กรอกให้ได้ทุกช่อง โครงการที่ไม่พบตัวเลขงบติ๊กเลือกได้ (นับเป็น 0 บาท) ตอนที่ 4 มีคำชี้แจงแนวทางการตอบและตัวอย่างสมมติ (ไม่บังคับ ไม่มีผลต่อการคำนวณ) ไฟล์ PDF ไม่ถูกส่งถึงผู้วิจัย ผู้วิจัยได้รับเฉพาะคำตอบที่ผู้ตอบกดส่ง และข้อมูลที่ส่งไม่มีเครื่องหมายว่ากรอกมาจากแผน (ผู้วิจัยแยกไม่ได้ว่าช่องใดกรอกเอง ช่องใดมาจากแผน)
- ตอนที่ 2–4 ของแบบสอบถาม (L, C, D, I และข้อเสนอแนะ) ไม่ถูกกรอกอัตโนมัติ เพราะเป็นการประเมินของผู้ตอบ
- ทดสอบ: `node tests/test_planread.js` (55 รายการ ใช้ข้อความสมมติ) ทดสอบกับไฟล์จริงได้ด้วย `node tools/plan_to_pages.js แผน.pdf pages.json` แล้ว `PLAN_PAGES_JSON=pages.json node tests/test_planread.js` (ไฟล์แผนจริงมีชื่อบุคคล อย่าเก็บไว้ใน repo)

## หลักฐานจากแผนปฏิบัติการใต้ข้อประเมิน 7-S (V0.13)

หน้า "ประเมินความพร้อม 7-S" แสดงป้ายหลักฐานจากแผนปฏิบัติการที่ผู้ใช้อัปโหลดไว้ใต้ข้อที่แผนอาจมีร่องรอยเอกสาร เพื่อให้ผู้อำนวยการหรือผู้รับผิดชอบตรวจและให้คะแนนเองได้เร็วขึ้น

- ครอบคลุม 11 ข้อ: STG1 STG4 STR1 STR5 SYS1 SYS5 STF2 STF4 SKL3 SKL6 STY4 แต่ละข้อแสดง "พบในแผน หน้า N พร้อมข้อความต้นฉบับ" หรือ "ไม่พบคำที่เกี่ยวข้อง (อาจมีเป็นเอกสารแยก)" และหมายเหตุว่าหลักฐานนั้นยังไม่ได้บอกอะไร (เช่น พบการอพยพ แต่ยังไม่ทราบว่าซักซ้อมจริงปีละครั้งหรือไม่)
- **ไม่ให้คะแนนและไม่เสนอคะแนน D หรือ I เริ่มต้น** เหตุผล: ข้อประเมินวัดการปฏิบัติจริง (เช่น ครูสังเกตสัญญาณเตือนได้ ผู้บริหารเป็นแบบอย่าง) แผนปฏิบัติการบอกเพียงสิ่งที่วางแผนไว้ และ I (สภาพที่พึงประสงค์) อ่านจากเอกสารไม่ได้เลย ถ้าเติมคะแนนล่วงหน้า ผู้ตอบมักยึดตามค่าที่เห็น (anchoring) และผลจะไม่ใช่การประเมินของผู้ตอบ ข้อที่ไม่มีป้ายคือข้อที่แผนไม่ใช่แหล่งหลักฐานที่เหมาะสม
- ใช้ในเครื่องมือประเมินเท่านั้น (ไม่ใส่ในแบบสอบถามของระบบรวบรวมข้อมูลวิจัย เพื่อไม่ชี้นำคำตอบ) ผลที่อ่านอยู่ในหน่วยความจำของเบราว์เซอร์และหายเมื่อรีเฟรช
- ทดสอบ: `node tests/test_planread.js` (63 รายการ) ทดสอบกับแผนจริง 1 ฉบับแล้ว พบ 5 จาก 11 ข้อ กฎคำค้นเขียนจากแผนฉบับเดียว ควรลองกับแผนของโรงเรียนอื่น

## แผนต้นแบบรายมาตรการ พิมพ์เป็น PDF (V0.14)

หน้า "แผนปฏิบัติการและติดตามผล" มีปุ่ม "แผนต้นแบบ (พิมพ์ PDF)" ที่แต่ละมาตรการ และปุ่ม "แผนต้นแบบทุกมาตรการ" (หน้า `#plandoc`) สร้างเอกสาร A4 รูปแบบแผนปฏิบัติการของโรงเรียนจากข้อมูลของมาตรการนั้นและผลประเมินของโรงเรียน

- หัวข้อ 7 ข้อ: หลักการและเหตุผล · วัตถุประสงค์ · ขั้นตอนดำเนินงาน (กรอบ 5 ขั้นจากข้อมูลมาตรการ) · ผลผลิตและผลที่คาดว่าจะได้รับ · ทรัพยากร งบประมาณ และเงื่อนไขก่อนดำเนินการ · ตัวชี้วัดและการติดตาม · หลักฐานทางวิชาการ พร้อมตารางข้อมูลหัวเรื่อง ช่องงบประมาณและค่าเป้าหมายให้เขียนเอง ช่องสถานะ และช่องลงนาม 3 ตำแหน่ง
- หัวข้อหลักฐานทางวิชาการแสดงระดับ A/B/C/D แหล่งอ้างอิง และข้อความหลักฐานของมาตรการนั้นตามข้อมูลในคลัง (ในคลัง 68 รายการ: A 3 · B 19 · C 30 · D 16) ไม่ได้อ้างว่าได้ผลดีทุกมาตรการ ระดับ C และ D ระบุตรง ๆ ว่ายังไม่มีงานวัดผลหรือยังไม่พบหลักฐาน และแนะนำให้เริ่มแบบนำร่อง คลังมาตรการยังเป็นฉบับร่างที่ยังไม่ผ่านเดลฟายและการตรวจหลักฐานรายข้อ

## ความสอดคล้องกับประกาศ ศธ. 7 มาตรการความปลอดภัยของสถานศึกษา (V0.15)

หน้า `#moe` (ปุ่มบนหน้าภาพรวม หรือลิงก์ "ประกาศ ศธ. 7 ข้อ" ในแถบเครื่องมือ) ตรวจว่าคลังมาตรการของระบบรองรับประกาศกระทรวงศึกษาธิการ เรื่อง มาตรการความปลอดภัยของสถานศึกษา (ลงวันที่ 10 สิงหาคม 2569) อย่างไร

- ข้อมูลอยู่ใน `moe.js` (ไม่มี DOM) ประกอบด้วยสรุป 7 ข้อ มาตรการ SB ที่เกี่ยวข้องของแต่ละข้อ ที่ระบบยังไม่ครอบคลุม และระดับความครอบคลุม ผลการจับคู่: ครอบคลุมดี 3 ข้อ (ข้อ 2, 3, 6) · ครอบคลุมบางส่วน 3 ข้อ (ข้อ 1, 4, 5) · ยังไม่มีมาตรการเฉพาะ 1 ข้อ (ข้อ 7 เขตพื้นที่ปลอดภัย)
- **ข้อจำกัดสำคัญ:** ไฟล์ประกาศเป็นภาพสแกนไม่มีชั้นข้อความ ผู้วิจัยอ่านจากภาพและสรุปเอง ไม่ใช่ข้อความทางการ ต้องตรวจกับฉบับจริงก่อนอ้างอิง การจับคู่กับ SB และระดับความครอบคลุมเป็นการประเมินของผู้วิจัยจากชื่อและคำอธิบายมาตรการ ยังไม่ผ่านการตรวจโดยผู้เชี่ยวชาญ
- มีรายการข้อเสนอเพิ่มในคลัง 7 รายการ (เช่น ศูนย์พิทักษ์สิทธิฯ ระดับสถานศึกษา เขตพื้นที่ปลอดภัย การเปิดพื้นที่ให้ผู้ปกครองสังเกตการณ์) **ยังไม่ได้เพิ่มเข้าคลัง** (คลังยังมี 68 รายการ) เพราะกระทบการเลือกมาตรการของระบบ จำนวนรายการและตารางในดุษฎีนิพนธ์ และต้องผ่านผู้เชี่ยวชาญก่อน
- ข้อ 7 มีหมายเหตุว่าการตรวจสัมภาระเกี่ยวข้องกับสิทธิและศักดิ์ศรีของผู้เรียน ระบบไม่ให้คำแนะนำทางกฎหมาย
- ผู้ใช้เลือกสถานะของโรงเรียนในแต่ละข้อได้ (ยังไม่มี · มีบางส่วน · ดำเนินการแล้ว) เก็บในหน่วยความจำของเบราว์เซอร์ หายเมื่อรีเฟรช
- แผนต้นแบบรายมาตรการ (PDF) ระบุข้อของประกาศที่เกี่ยวข้องกับมาตรการนั้น (14 จาก 24 แผนในตัวอย่าง)
- ทดสอบ: `node tests/test_moe.js` (13 รายการ)

## เล่มแผนปฏิบัติการด้านความปลอดภัยสถานศึกษา แบบทางการ (V0.16)

หน้า `#planbook` (ปุ่มบนหน้า "แผนปฏิบัติการและติดตามผล") สร้างเล่มแผนปฏิบัติการสำหรับพิมพ์หรือบันทึกเป็น PDF ใช้รูปแบบแผนปฏิบัติการความปลอดภัยของกระทรวงศึกษาธิการ

- รูปแบบ: A4 แนวนอน ตัวอักษร TH Sarabun New 16 pt (ตาราง 14 pt) ตัวเลขไทย เลขหน้า และสารบัญที่มีเลขหน้าตรงกับหน้าที่พิมพ์จริง ปก · สารบัญ · ส่วนที่ 1 ข้อมูลทั่วไปและผลการประเมิน · ส่วนที่ 2 ตัวชี้วัดและความสอดคล้องกับ 7 มาตรการของ ศธ. · ส่วนที่ 3 ตารางแผนปฏิบัติการ · ส่วนที่ 4 การติดตาม ประเมินผล และลงนามอนุมัติ · ภาคผนวกเอกสารอ้างอิงและหลักฐานทางวิชาการ
- ตารางแผนปฏิบัติการใช้ 6 คอลัมน์ตามแผนของ ศธ. (ระยะเวลา · ชื่อโครงการ · หลักการ · วัตถุประสงค์ · การดำเนินการ · การติดตาม/ประเมินผล) ชื่อโครงการระบุรหัส SB ผู้รับผิดชอบ ระดับหลักฐาน และข้อของประกาศ ศธ. ที่เกี่ยวข้อง
- ตัวชี้วัดของกระทรวง: ใช้ตัวชี้วัด "ระดับความสำเร็จในการจัดการศึกษาเพื่อความปลอดภัย" พร้อมเกณฑ์ 3 ระดับ (ขั้นต้น 50 · มาตรฐาน 75 · ขั้นสูง 100) จาก **แผนการปฏิบัติการความปลอดภัย ปีงบประมาณ พ.ศ. 2566** ของ ศธ. เป็นต้นแบบ **เป็นตัวชี้วัดของปี 2566 ไม่ใช่ปีปัจจุบัน** เอกสารระบุไว้ให้ตรวจกับตัวชี้วัดของปีปัจจุบันจากต้นสังกัดก่อนใช้จริง ผู้วิจัยยังไม่มีตัวชี้วัดปีงบประมาณ 2569
- ความสอดคล้องกับ 7 มาตรการ (ตารางข้อ 2.2): คำนวณจากโครงการที่อยู่ในแผนจริง ข้อที่ไม่มีโครงการรองรับแสดงว่า "ยังไม่มีโครงการรองรับในแผนนี้" ตัวอย่างโรงเรียนสมมติครอบคลุม 4 จาก 7 ข้อ
- ตัวชี้วัดความสำเร็จของแผน (ข้อ 2.3) คำนวณจากข้อมูลจริงในแผน ค่าเป้าหมายเป็นข้อเสนอเริ่มต้นที่โรงเรียนปรับได้ ไม่มีตัวเลขที่แต่งขึ้น
- ภาคผนวกแสดงเอกสารอ้างอิง ระดับหลักฐาน A/B/C/D ของโครงการในแผน และแหล่งอ้างอิงเฉพาะที่โครงการในแผนใช้ พร้อมหมายเหตุว่าคลังมาตรการเป็นฉบับร่าง
- การแบ่งหน้า: วัดความสูงจริงในเบราว์เซอร์แล้วจัดแถวตารางลงหน้า (ไม่ตัดกลางแถว หัวตารางซ้ำทุกหน้า หัวข้อไม่ค้างท้ายหน้า) แล้วเติมเลขหน้าในสารบัญ ทดสอบโดยพิมพ์หน้าจริงด้วย Chrome headless เป็น PDF 19 หน้า ตรวจเลขหน้าในสารบัญ 16 รายการตรงทั้งหมด

- ทดสอบ: `node tests/test_planbook.js` (36 รายการ ครอบคลุมโครงเล่ม ความสอดคล้อง 7 ข้อ การคำนวณตัวชี้วัด การอ้างอิง ตัวเลขไทย การป้องกันการแทรกโค้ด และอัลกอริทึมแบ่งหน้า)

## ฐานงานวิจัยของแต่ละมาตรการ (V0.17)

แผนต้นแบบรายมาตรการ (หัวข้อ 2 "ต้นแบบและงานวิจัยที่รองรับ") และเล่มแผนปฏิบัติการ (ภาคผนวก ก–ค) แสดงฐานของมาตรการแยก 3 ชั้น ตามหลักฐานที่มีจริง

- **(ก) ฐานแนวคิดและนโยบายจากบทที่ 2** คำนวณจากข้อมูลของมาตรการ: เสาหลัก CSSF 2022–2030 (จากช่อง pillar ของมาตรการ ข้อ 2.3.2) · ขอบข่ายภัย 4 กลุ่มและมาตรการ 3 ป. (กระทรวงศึกษาธิการ 2564 ข้อ 2.3.5) · ISO 31000 (ข้อ 2.4) · 7-S (ข้อ 2.2) · โครงสร้างแผนตาม Hrebiniak (ข้อ 2.8) · วงจรวิกฤต Liou (ข้อ 2.7) เฉพาะมาตรการตอบสนองและฟื้นฟู · หลักฐานปัญหาออนไลน์ (ข้อ 2.3.4) เฉพาะมาตรการออนไลน์ โดยระบุว่าเป็นหลักฐานว่าปัญหามีอยู่ ไม่ใช่หลักฐานว่ามาตรการได้ผล
- **(ข) ต้นแบบในโรงเรียนไทย** งานวิจัยและพัฒนากลยุทธ์หรือรูปแบบความปลอดภัยสถานศึกษา 4 เรื่องจากตารางที่ 2.1 (ข้อ 2.9.1) ผลหลักมาจากบทคัดย่อ เป็นชุดกลยุทธ์หรือรูปแบบสำหรับพื้นที่ที่ศึกษา ไม่ใช่หลักฐานว่ามาตรการแต่ละข้อได้ผล
- **(ค) หลักฐานของผลมาตรการ** ระดับ A–D แหล่ง และข้อความหลักฐานจากคลังมาตรการ พร้อมสถานะว่าแหล่งนั้นอยู่ในบทที่ 2 หรือไม่
- **ข้อค้นพบสำคัญ:** จาก 29 แหล่งหลักฐานในคลังมาตรการ มีเพียง 3 แหล่งที่อยู่ในบทที่ 2 ของโครงร่างฯ v14 (CSSF · Marzban 2026 · พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล 2562 ผ่านงานของอภิภัสร์ และคณะ 2569) อีก 26 แหล่ง (เช่น Gaffney 2021 · Cipriano 2023 · Lester 2017) **ยังไม่อยู่ในบทที่ 2 และรายการอ้างอิง** และคลังมีสถานะ "ยังไม่ตรวจ" เอกสารแจ้งสถานะนี้ตรง ๆ ไว้ทุกแผน ต้องเพิ่มและตรวจที่มาของ 26 แหล่งก่อนอ้างอิงในเอกสารทางการและก่อนแก้บทที่ 2

## หลักการและเหตุผลของแผนจากผลวิเคราะห์ของระบบ (V0.18)

ข้อ 1 ของแผนต้นแบบรายมาตรการ ("หลักการและเหตุผล (ที่มาของแผน)") ประกอบจากผลวิเคราะห์ของระบบ แล้วอ้างอิงสั้น ๆ ว่าแต่ละประโยคมาจากไหน (ผู้แต่ง ปี · ข้อของบทที่ 2) ไม่ใส่รายละเอียดงานวิจัย `EV.rationale(m, ctx)` ใน `evidence.js` สร้างข้อความ 4 ส่วน:

1. **สถานการณ์ที่ระบบวิเคราะห์ได้** ความเสี่ยงของด้าน (ดัชนี R จากโอกาส × ผลกระทบ, ISO 2018 ข้อ 2.4) ความพร้อมตาม 7-S (McKinsey 2008 ข้อ 2.2) และกลุ่มแนวทาง R1–R9 จากตารางตัดสินใจ
2. **เหตุผลที่ต้องมีมาตรการนี้** องค์ประกอบ 7-S ที่มาตรการเสริม (บอกอันดับช่องว่างเมื่ออยู่ใน 3 อันดับแรก) ประเภท 3 ป. และขอบข่ายภัย (ศธ. 2564) เสาหลัก CSSF (GADRRRES 2022) ข้อของประกาศ ศธ. 10 ส.ค. 2569 ที่เกี่ยวข้อง และหลักฐานว่าปัญหาออนไลน์มีอยู่ (เฉพาะมาตรการที่เกี่ยวกับออนไลน์ พร้อมระบุว่าไม่ใช่หลักฐานว่ามาตรการได้ผล)
3. **เหตุผลที่วางแผนในรูปแบบนี้** โครงแผน (ผู้รับผิดชอบ ทรัพยากร ตัวชี้วัด รอบทบทวน) ตาม Hrebiniak 2006 ข้อ 2.8 และต้นแบบในโรงเรียนไทย 4 เรื่อง (ข้อ 2.9.1) พร้อมระบุว่าเป็นชุดกลยุทธ์ของพื้นที่ที่ศึกษา
4. **งานวิจัยที่รองรับผลของมาตรการนี้** ระดับ A–D พร้อมแหล่งและข้อของบทที่ 2

ข้อ 2 ของแผนเหลือเฉพาะข้อความหลักฐานของคลังและข้อควรระวัง เล่มแผนปฏิบัติการเพิ่มบรรทัด "อ้างอิง: ..." ในช่องเหตุผลของทุกโครงการ และภาคผนวกพิมพ์เอกสารอ้างอิงเต็มของแหล่งที่ใช้

- **แหล่งหลักฐาน 26 แหล่งอยู่ในบทที่ 2 แล้ว** ตั้งแต่โครงร่างดุษฎีนิพนธ์ฉบับ v15 (ข้อ 2.9.4 ตารางที่ 2.5) เว็บจึงอ้างว่าอยู่ในบทที่ 2 ข้อ 2.9.4 ทุกแหล่ง และไม่มีป้าย "ยังไม่อยู่ในบทที่ 2" อีก แต่ผู้วิจัยยังไม่ได้อ่านเนื้อเต็ม และรายการอ้างอิงที่ขาดเลขหน้าหรือ DOI มีวงเล็บเหลี่ยมกำกับในข้อความเต็ม
- เล่มแผนแปลงตัวเลขเป็นเลขไทย แต่ไม่แปลง URL และ DOI ในรายการอ้างอิง
- ทดสอบ: `node tests/test_evidence.js` (109 รายการ) และ `node tests/test_planbook.js` (45 รายการ) พิมพ์จริงด้วย Chrome headless: แผนต้นแบบ 24 แผนพอดี 24 หน้า A4 เล่มแผน 25 หน้า A4 แนวนอน ไม่ล้นหน้า

## แผนดำเนินการรายมาตรการ (V0.19)

ข้อ 4 ของแผนต้นแบบ และคอลัมน์ "การดำเนินงาน" ในเล่มแผนปฏิบัติการ เปลี่ยนจากรายการหัวข้อ 5 ข้อ เป็นแผนดำเนินการ 6 ขั้นที่มีช่วงเวลา กิจกรรม ผู้รับผิดชอบ และผลที่ได้ (`actplan.js` ฟังก์ชัน `steps(m, ctx)`):

1. สัปดาห์ที่ 1 ประชุมมอบหมายงาน ตรวจเงื่อนไขก่อนดำเนินการ (ระบุรหัสมาตรการที่ต้องมีก่อน)
2. เตรียมทรัพยากรตามที่มาตรการระบุ พร้อมแจ้งว่าต้องขออนุมัติงบหรือไม่ตามระดับทรัพยากร 1–3
3. ดำเนินกิจกรรมหลักตามข้อความของมาตรการ (คำนำต่างกันตามช่วง ป้องกัน เตรียมพร้อม ตอบสนอง ฟื้นฟู)
4. ทดลองใช้หรือซ้อมตามช่วงของมาตรการ (ฟื้นฟูทดลองด้วยกรณีจำลอง ไม่ใช้ข้อมูลจริงของนักเรียน)
5. ประกาศใช้ สื่อสาร และเก็บหลักฐานตามผลผลิตของมาตรการ
6. วัดผลด้วยตัวชี้วัดของมาตรการและทบทวนตามรอบของกลุ่ม R

- ระยะรวมตามระดับทรัพยากร: ระดับ 1 = 4 สัปดาห์ ระดับ 2 = 8 สัปดาห์ ระดับ 3 = 12 สัปดาห์ นับจากวันเริ่มดำเนินการของกลุ่มแนวทาง โรงเรียนปรับให้ตรงปฏิทินของตน
- **ข้อจำกัด:** แผนนี้ประกอบจากข้อมูลของมาตรการในคลังกับกรอบขั้นตอนตามช่วง ไม่ใช่แผนที่ผู้เชี่ยวชาญเขียนรายมาตรการ ระยะเวลาและขั้นตอนยังไม่ผ่านเดลฟาย
- ทดสอบ: `node tests/test_actplan.js` (15 รายการ) พิมพ์จริงด้วย Chrome headless: แผนต้นแบบ 24 แผนพอดี 24 หน้า A4 เล่มแผน 25 หน้า ไม่ล้นหน้า

### ขั้นตอนเฉพาะรายมาตรการ (V0.20)

ขั้น 3 (ดำเนินกิจกรรม) ขั้น 4 (ทดลองใช้หรือซ้อม) และขั้น 5 (ประกาศใช้และเก็บหลักฐาน) ของแผนดำเนินการ เขียนเฉพาะรายมาตรการครบทั้ง 68 รายการใน `actsteps.js` รูปแบบ "หัวข้อสั้น: รายละเอียด" ไม่เกิน 140 ตัวอักษรต่อข้อ ให้พอดี 1 หน้า A4 ส่วนขั้น 1 2 และ 6 ยังเป็นกรอบกลางจากข้อมูลมาตรการ (`actplan.js`) ถ้ามาตรการใดไม่มีรหัสคลังหรือไม่มีข้อความเฉพาะ ระบบกลับไปใช้กรอบทั่วไปตามช่วง

- ผู้วิจัยเขียนจากชื่อ คำอธิบาย ผลผลิต และเงื่อนไขก่อนดำเนินการของแต่ละมาตรการ **ยังไม่ผ่านเดลฟายและไม่ใช่คำแนะนำทางกฎหมายหรือการแพทย์** มาตรการเรื่องกฎหมาย ข้อมูลส่วนบุคคล และสุขภาพจิต ให้ปรึกษาต้นสังกัดหรือผู้เชี่ยวชาญก่อนใช้จริง
- เล่มแผนปฏิบัติการใช้หัวข้อสั้นของแต่ละขั้นในคอลัมน์ "การดำเนินงาน"
- ทดสอบ: `node tests/test_actplan.js` (27 รายการ ครอบคลุมครบ 68 มาตรการ ความยาว รหัสมาตรการที่อ้างต้องมีในคลัง และถ้อยคำเรื่องข้อมูลอ่อนไหว) พิมพ์จริง: แผนต้นแบบ 24 แผน 24 หน้า A4 เล่มแผน 25 หน้า ไม่ล้นหน้า

### รูปแบบหน้ากระดาษทางการของแผนต้นแบบ (V0.21)

- ต้องติดตั้งฟอนต์ TH Sarabun New ในเครื่อง ถ้าไม่พบ หน้าเว็บแจ้งเตือนและใช้ฟอนต์สำรอง ตอนพิมพ์ให้ใช้ขอบ "ค่าเริ่มต้น" และปิด "ส่วนหัวและส่วนท้าย"
- ไม่ใช้ตราครุฑ เพราะแผนนี้ไม่ใช่หนังสือราชการ ใช้ตราโรงเรียนที่ผู้ใช้ตั้งไว้เหมือนเดิม

### แบบบันทึกผลการนำแผนไปใช้ (V0.24)

โรงเรียนที่นำแผนรายมาตรการไปใช้ บันทึกผลกลับมาให้ผู้วิจัย เพื่อดูว่าแผนที่ระบบเสนอตอบสนองกลยุทธ์และวัตถุประสงค์อย่างไร พึงพอใจหรือพบอุปสรรคอะไร

- **ชนิดแบบฟอร์ม `planreport`** (`planrec.js`) อยู่ในระบบรวบรวมข้อมูลเดิม ใช้รหัสโรงเรียน ความยินยอม โหมด demo/tryout/live และเส้นทางส่งเดียวกับแบบที่ 1–3 หนึ่งรายงานต่อหนึ่งมาตรการ ข้อมูล: สถานะและหลักฐานของ 6 ขั้นตอนตามแผน ผลตัวชี้วัด (ค่าเป้าหมาย ค่าจริง ผลเทียบเป้า) จำนวนผู้เข้าร่วมจริงเทียบที่ตั้งใจ ผู้ปฏิบัติงาน ชั่วโมง ค่าใช้จ่าย สัปดาห์ที่ใช้จริง สถานการณ์ด้านนั้นหลังใช้แผน (และจำนวนเหตุก่อน–หลังถ้ามี) ความสอดคล้องกับกลยุทธ์ A1–A6 ความพึงพอใจ S1–S5 อุปสรรค และข้อความสั้นที่ห้ามมีชื่อบุคคล (ตรวจทั้งฝั่งเบราว์เซอร์และ `apps-script/collect.gs`)
- **หน้ากรอกออนไลน์ `#planrec`** (แท็บ "4 ผลการใช้แผน" ในระบบรวบรวมข้อมูล): เลือกมาตรการในแผนของโรงเรียนหรือจากคลัง แถวขั้นตอนตรงกับแผนของมาตรการนั้น ฉบับร่างเก็บแยกรายมาตรการในเครื่อง ลิงก์ตรง `#planrec?s=รหัสโรงเรียน&m=SB-004`
- **แบบพิมพ์ `#recform`**: แบบบันทึกผลรายมาตรการรูปแบบทางการเดียวกับแผนต้นแบบ (TH Sarabun New 16 pt ขอบ 3/2/1.5/2 ซม.) ลำดับส่วนที่ 1–9 และรหัส A1–A6 S1–S5 ตรงกับหน้ากรอก ให้โรงเรียนจดระหว่างทำแล้วนำไปกรอกในโปรแกรม ปุ่ม "แบบบันทึกผล" และ "กรอกผลในโปรแกรม" อยู่ในทุกแถวของหน้าแผนปฏิบัติการ
- **ป๊อปอัป**: เมื่อพิมพ์หรือบันทึกแผน (หน้าแผนปฏิบัติการ แผนต้นแบบ เล่มแผน หรือดาวน์โหลด CSV) ขึ้นข้อความให้นำข้อมูลที่ได้จากการใช้แผนมากรอกในโปรแกรม พร้อมปุ่มไปหน้ากรอก พิมพ์แบบบันทึกผล หรือไว้ทีหลัง (กด Esc ปิดได้)
